# Cozy Focus Pet: implementation progress

The MVP is **in progress**. This file tracks the [product plan](IMPLEMENTATION_PLAN.md), current gaps, and known handoff issues.

## Known performance issue: schedule calculation blocks the app

**This is a handoff priority for the planned Electron rewrite.** The suggested-day algorithm is expensive in the current Debug build. The app previously ran it on the main thread after timer event writes, so starting focus or a break took about 4 seconds and ending one took about 10 seconds in one isolated Testing sequence. Later commands exceeded the 15-second control timeout, and the Testing process was no longer running when checked. The reason it exited is unconfirmed. A main-thread sample traced the delay through `AppModel.refreshSummary`, `DayProjection.project`, and `DayPlanner.optimize`.

Commits `71448d0` and `ace2ce7` are on this branch. The first stops timer event summaries from rerunning the planner and computes one shared plan timeline when plan inputs change. The second lets Today use completed focus and break intervals for its next recommendation. After the first fix, five focus starts, five focus ends, five break starts, and five break ends each returned in about one second through the development control loop, which polls once per second. The updated Today behavior has 42 passing core tests and a successful macOS build in its isolated implementation worktree. The combined branch has not had a fresh full app smoke run.

**Plan edits remain slow.** Changing both focus and break lengths still took about 5.5 seconds in Testing. The current code can call `savePlan` separately from each setting change and again from the Settings view or development command. One 8-hour plan took 1.25 to 1.29 seconds for a single `DayPlanner.suggest` call in five isolated Debug runs. A disposable experiment removed duplicate save triggers, but that change is not on this branch and still left a synchronous planner call. Do not treat the timer fix as proof that plan editing is responsive.

Today uses completed sessions for the next recommendation, but it does not fully reschedule all future blocks after actual work or breaks. For the Electron rewrite, keep schedule optimization off the renderer and main process UI paths. Recalculate when plan inputs, meetings, or relevant completed-session facts change; coalesce rapid edits and publish the plan with its matching blocks as one versioned result. Clock and countdown updates should read that result without rerunning the optimizer. Preserve append-only facts, profile-separated databases, and the distinction between planned blocks and actual focus or break intervals. The intended next product area is a configurable passive room or town; the character and world design are still undecided.

## Working workflows

- **Personal:** `scripts/run-personal.sh` builds and opens the normal app. Startup chooses Personal; Settings can switch profiles for a session. The app has a menu bar icon and no Dock icon.
- **Agent:** `scripts/run-dev.sh` builds one background app locked to `.build/dev-state/events.sqlite`. `scripts/dev-control.sh status` should report `profile=testing` and `appActive=false`; `screenshot` returns a PNG of only that app window. `scripts/ui-smoke.sh` resets only Testing and checks a full focus/break/reward loop.
- **Browser:** `scripts/chrome-smoke.sh` uses an isolated Chromium profile. Chrome DevTools MCP can inspect the running browser when available; it is separate from native-window screenshots.

Current verification: 42 core tests pass in the isolated Today implementation worktree, and its Xcode app builds. The full app smoke checks described below ran before the latest performance and Today changes; rerun them before treating this branch as verified. Earlier isolated checks passed a full focus and break cycle, timeline and meeting model edits, reflection and plan replay, interrupted-session recovery, simulated idle, lock, sleep, and clock changes, screenshots, and quit. `scripts/today-smoke.sh` covered plan changes, timer targets, meeting transitions, and day rollover. App-owned Today, meeting editor, room, and Settings screenshots were inspected in the background. Both browser smoke modes passed. The Personal launcher has not been run, so verification has not opened the user's database.
